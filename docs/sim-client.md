# 模拟客户端

内部测试用的交易页面，扮演"合作方的后端"接入我们的`contract-api`：可以在页面上交易、看盘口和K线、做运营操作，
还能接币安的公开行情做 **系统做市**——用户的对手方就是系统。

它不是产品，不进生产镜像，代码在`tools/sim-client/`。

## 为什么需要一层代理

浏览器不能直接连我们的后端：

- 鉴权是API Key + HMAC签名， **密钥不能放进页面**
- 浏览器的WebSocket API不能自定义请求头，`/ws`握手的签名也做不了

所以页面只连一个薄的代理服务，代理持有密钥、对每个请求签名后转发，WebSocket也由它签名连上去再中继给页面。
这也说明：真实的合作方如果有网页端，同样得经过自己的后端转发，不能让浏览器直连我们。

```
浏览器页面  →  代理(tools/sim-client，持有密钥、签名、转发HTTP和WS)  →  contract-api / contract-engine
                     │
                     └→ 系统做市：币安公开行情(REST) → 镜像成我们订单簿里的真实挂单
```

签名用的是生产代码里的`api.SignRequest`，跟合作方对接用的是同一套。

## 怎么用

```bash
cp deploy/.env.test.example deploy/.env      # 把PERP_API_KEYS里的CHANGE_ME换成随机串
make compose-test-up                         # 拉起整套系统
make sim-client                              # 打开 http://127.0.0.1:8088
make sim-client ARGS='-maker'                # 启动时就开启系统做市
```

`scripts/sim-client.sh`会从`deploy/.env`里取第一把带`ops`权限的密钥和后端端口。可选参数见
`go run ./tools/sim-client -h`，环境变量`SIM_*`也能配置。

## 页面功能

- **账户**：新建账户并充值、切换账户，显示权益、可用余额、仓位保证金、挂单冻结、未实现盈亏、信用额度、轮次
- **交易**：限价/市价，开仓/平仓，杠杆，只减仓；点订单簿的价格自动填入；按余额或持仓的百分比填数量；预估名义价值、
  保证金和手续费
- **行情**：订单簿（引擎实时）、最新成交、K线（六个周期）、标记价/指数价/24h统计/预估资金费率
- **持仓和委托**：持仓（含浮盈亏、回报率、强平价估算，市价平仓、改杠杆）、当前委托（撤单、撤销全部）、条件单、
  委托历史、成交历史（含maker/taker角色）、资金流水、强平记录
- **运营抽屉**：冻结/解冻、发信用额度、扣减余额、设投保、结束本轮、设指数价
- **API调用日志**：每次调用的请求、响应、耗时，点击展开，方便看接口对接时到底发了什么、收到了什么
- **实时**：WebSocket推送深度、成交、K线、标记价、账户快照；每5秒用REST校准一次（WS不保证绝对不丢）

## 系统做市（币安行情）

只有一个用户的话什么都成交不了。系统做市把币安的盘口镜像成我们订单簿里的 **真实挂单**，用户的单子跟它们走真实的
撮合和结算，成交的对手方就是系统。

四个系统账户（uid从`-maker-uid-base`起，默认9000000，占4个）：

| uid偏移 | 作用                                      |
|---------|-------------------------------------------|
| +0      | 买盘做市（开多挂买单）                    |
| +1      | 卖盘做市（开空挂卖单）                    |
| +2 / +3 | 对敲买 / 对敲卖，用来把标记价拉到币安价格 |

**盘口镜像**：每2秒拉一次币安的深度（500档）和标记价/指数价，按价格桶聚合（BTC约5美元一档，ETH约0.2美元，
按价格自动选1/2/5×10的整数次幂），买盘向下取整、卖盘向上取整（保证买一低于卖一，我们自己的两侧挂单不会交叉），
每侧取最靠近成交价的12档，数量是币安对应价格桶里的真实数量之和。跟已挂着的单子做差异：价格不在期望里的撤、缺的补、
被用户吃掉大半的撤了重挂， **行情没变就什么都不动**（不天天撤了重挂，也不丢排队位置）。币安某个价位的挂单量波动
不会触发重挂，被吃掉大半是跟"下单时的数量"比的。

**对敲**：我们的标记价就是最新成交价，没有用户交易时会停在很久以前，页面上的盈亏、强平价、K线都不跟着行情走。
所以偏离上次对敲价超过0.01%（最短间隔5秒），或者超过60秒没对敲过，就让两个对敲账户在我们的买一卖一中点成交一笔最小量。
K线上会看到这些很小的成交。指数价也从币安同步过来，资金费率的溢价率才有参照。

**行情情景（测试强平、盈亏）**：价格跟着币安走，要让一个10倍多头被强平需要行情下跌约10%，等不到，也没法手动制造。
所以做市可以在币安价格之上叠加一个偏移：运营抽屉里的"行情情景"（-1%、-5%、-10%、+5%、+10%、自定义、回到币安价），整个盘口
和指数价乘上 `1 + 偏移%`，顶栏会标出"行情情景 -7% 偏移"。偏移 **逐步推进**，每个周期（2秒）最多1个百分点，不能一步跳过去：
开仓限价单有5%的价格保护带（偏离标记价超过5%会被拒），报价和标记价必须一步步走，推进期间每个周期都对敲，标记价才跟得上。
重新启动做市时会先按我们现有的标记价反推当前偏移再往目标走，所以不会因为上次的情景没走回来而卡住。范围±30%。

偏移只存在于这个工具里：后端看到的只是价格在动（成交价、指数价在变），走的是真实的撮合、风控、强平流程，生产环境用真实的币安行情
时不需要也不存在这个功能。

**在页面上测试强平**：

1. 开启做市，新建一个账户， **只充值一点钱**（比如1000）
2. 杠杆10，选"市价"，点"100%"按钮，买入开多——满仓
3. 运营抽屉里点"-5%"看浮亏（未实现盈亏、回报率、权益都在变），再点"-10%"
4. 行情下移到接近强平价（持仓表里有估算强平价）时，右下角会提示"仓位进入强平"，仓位状态变成"强平中"，强平单按保护价
   挂出、吃系统的买盘，完成后提示"强平完成"，仓位清零；"强平记录"标签页里有强平委托（委托价是保护价，成交价是实际吃到的价格），
   "资金流水"里有已实现亏损和手续费
5. 强平点大约在"亏损 = 保证金 - 维持保证金"处：10倍多头约下跌9.6%。真实币安价格自己也在波动，所以触发时的偏移会有出入

**在页面上验证盈亏**：开仓后点"+2%"，持仓表里的未实现盈亏 = (标记价 - 开仓均价) × 数量，权益 = 可用余额 + 仓位保证金 +
未实现盈亏；
市价平仓后，"资金流水"里已实现盈亏 = (平仓成交价 - 开仓成交价) × 数量，余额 = 充值 + 已实现盈亏 - 手续费。

**开关和重置**：页面右上角的"做市"标签和运营抽屉里可以开关。关闭（或退出程序）时会撤掉系统账户在订单簿里的全部挂单，
不留过期报价。做市账户只开仓不平仓，仓位会随着用户交易累积（多空各一份、不轧差），用余额（默认10亿USDT，低于一半
自动补）兜着；累积多了点"重置系统账户"，会停掉做市、结束本轮（按标记价平掉全部仓位）。

**限制**：

- 用REST轮询，不是WebSocket，我们的盘口跟币安有一个刷新周期的滞后；实测买一卖一跟币安中间价相差在±10到16美元以内
  （约0.01%到0.02%），偶尔换档时有一个周期内的短暂错位。撤单是异步的（经Kafka），所以换档时先撤旧单、再补新单，
  新挂的买单必须低于所有还挂着的卖单（含刚发出撤单请求、还没摘掉的），新挂的卖单必须高于所有还挂着的买单，被挡下的档位留到
  下个周期补——否则行情上行时新买单会跟没摘掉的旧卖单成交，两个系统账户之间真实成交、把最新成交价拖回过期的价格
- 币安在部分地区不可访问（返回451），被限流会返回429/418，错误会显示在运营抽屉里，出错时不会动订单簿里已有的挂单
- 只有BTCUSDT和ETHUSDT两个合约（`-maker-symbols`可以改，但必须是币安上也有的合约名）
- 数量的缩放（`-maker-scale`，默认1）是按币安的真实数量，用户下很大的单会吃穿12档，市价单吃不满的部分会撤销

## 安全

代理持有`ops`权限的密钥（能充值、冻结、设指数价），所以：

- **默认只绑127.0.0.1**，监听其他地址会拒绝启动（`-allow-remote`可以强行放开，但等于任何人都能加钱扣钱）
- **只接受回环名字访问**（校验`Host`头），防DNS重绑定
- **`/api`、`/engine`、`/sim`必须带自定义请求头`X-Sim-Client`**：别的网站的页面借用户的浏览器发请求，没法在不触发
  CORS预检的前提下加自定义请求头，而代理不响应预检
- **WebSocket校验`Origin`**必须是代理自己的页面
- **不跟随重定向**：请求带着签名头，跟着重定向去了别的地址就把API Key送出去了

**已知的局限**：代理不认证调用方，也没有路径或方法白名单——同一台开发机上的任何本地进程或其他系统用户，加上`X-Sim-Client`头就能
经它用ops权限调用后端（加减余额、冻结账户）。它跟任何本机开发服务器（数据库、调试端口）是同一类风险，前提是开发机本身可信；
上面几条防的是浏览器里的跨站攻击，不是本机上的其他进程。不要在多用户共用的机器上运行，也不要暴露到网络上。

## 测试

`go test ./tools/...`（也包含在`go test ./...`里）覆盖：

- **代理**：转发时签名覆盖的路径/查询串/请求体跟实际转发的一致（用生产的验签方式重新算一遍）、`/api`前缀被去掉、
  没配密钥就不签名、三道防护、监听地址检查
- **做市的纯逻辑**：价格桶聚合（买盘向下、卖盘向上、买一桶一定低于卖一桶）、数量缩放、差异计划（缺的补、多的撤、
  被吃掉的重挂、不为币安数量变化反复重挂）、行情情景的偏移推进和价格平移
- **做市循环**（假的后端加假的币安）：第一个周期买卖各挂满、同步指数价、对敲；行情没变第二个周期不动档位；档位被吃掉后
  补回；停止时撤掉全部系统挂单；后端出错记录错误；币安连不上（451）时不动已有挂单；`requestId`格式合法；行情情景：
  盘口和指数价都乘上偏移系数、每个周期只推进一步到目标后停住、启动时按我们现有的标记价反推当前偏移、偏移范围限制

页面本身没有自动化测试，是用无头Chrome通过DevTools协议驱动验证的，驱动的是页面上的真实点击：新建账户、充值、点盘口填价、
下单、成交、持仓、挂单、撤单、市价平仓、成交历史、资金流水；以及强平和盈亏场景——充值1000满仓10倍市价开多，行情下移3%时
页面显示的未实现盈亏与手算一致（-299.77），继续下跌在约-9%触发强平，强平单以保护价挂出、按系统买盘成交，仓位清零、账户归零，
强平记录和资金流水里都有明细；另一个账户开仓后行情上涨，已实现盈亏与 (平仓价-开仓价)×数量逐分一致，余额与
充值+盈亏-手续费一致。控制台无错误。

## 它发现过的问题

页面第一次实际交易就暴露了两个后端的真实缺陷（都已修复，见对应提交和测试）：

- **市价单撮合不成交**：`contract-api`把标记价存进市价单的`price`字段，引擎原样传给撮合，市价单变成"按标记价成交的
  限价单"，市价买只能吃低于等于标记价的卖单，几乎一笔都成交不了，见 [matching-and-settlement.md](matching-and-settlement.md)
- **每笔下单撤单固定多1秒延迟**：Kafka生产者用了kafka-go默认的`BatchTimeout`（1秒），同步单条写入要等满；
  默认的`RequiredAcks`还是不等确认。现在是10ms和等全部副本确认
