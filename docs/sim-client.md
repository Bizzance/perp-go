# 模拟客户端

内部测试用的交易页面，扮演"合作方的后端"接入我们的`contract-api`：可以在页面上交易、看盘口和K线、做运营操作。

它不是产品，不进生产镜像，代码在`tools/sim-client/`。**用户的对手方是系统**——把币安订单簿镜像进我们订单簿这件事
由`contract-engine`内部的`MirrorService`负责（见 [orderbook-sync.md](orderbook-sync.md)），不是这个页面/代理自己做的；
模拟客户端只是一个薄的签名转发层，没有自己的做市逻辑。要在本地看到有深度的订单簿，配置`PERP_MIRROR_SYMBOLS`
启动`MirrorService`即可，见 [orderbook-sync.md](orderbook-sync.md)。
**K线来源**：开了订单簿镜像时设`PERP_KLINE_SOURCE=external`，K线、24h统计、最新价都是币安的，页面上的最新价跟着
K线收盘价走；不开镜像、只有用户之间真实成交时保持默认的`PERP_KLINE_SOURCE=trades`。
**持仓盈亏实时重算**：服务端不会因为标记价变化推送持仓，页面收到`markprice`推送后自己按新标记价重算持仓行的标记价、未实现盈亏、回报率和账户面板的
未实现盈亏、权益（`app.js`的`recomputeForMark`，公式跟服务端一致），下一次服务端推送或5秒一次的REST刷新会用服务端的值覆盖。

## 原则：按合作方对接的方式做

模拟客户端就是"第一个合作方"：**只通过公开的对接接口拿数据、做事**，不走任何后门。这样合作方以后遇到的问题，我们能提前在这里测出来。具体做法：

- 价格/数量显示几位小数取自`GET /contract/list`的`priceScale`/`baseCoinScale`，末尾的0也显示；最大杠杆取自`/contract/detail`的分档；手续费取自它的`takerFee`，都不写死
- 下单输入按`/contract/detail`的规则约束：位数不超过`priceScale`/`baseCoinScale`，是`priceTick`/`volumeStep`的整数倍，不小于`minVolume`、不超过`maxVolume`
  （`priceTick`/`volumeStep`是0时按位数）。判断整数倍用整数运算，不经过浮点数。百分比按钮也按数量步长取整。这曾经出过问题：百分比按钮写死了3位小数，
  ETH的数量精度是2位，下出了`88.931`这样的数量，而服务端当时没配步长、照收了
- 数量输入框旁边可以在"币 / USDT名义价值"之间切换：选USDT时，页面按`数量 = floor(名义价值 ÷ 价格 ÷ 数量步长) × 数量步长`换算成币的数量再提交
  （限价单用委托价，市价单用标记价，全部按整数运算），服务端收到的仍然只有币的数量，见 [api.md](api.md)"按USDT下单怎么换算"。切换单位时输入框里已有的数量会换算成另一种单位
- 持仓盈亏不随标记价推送，页面订阅`markprice`频道自己重算，跟合作方要做的一样，见 [websocket.md](websocket.md)
- 深度走contract-engine自己的`/depth`（合作方也是这样），私有数据走签名的REST和WebSocket

**跟真实对接还有的差别**（发现了要么补上，要么写在这里）：

- 代理默认只用一把密钥，同时有`trade`和`ops`权限，这时"某个接口的权限范围分错了"测不出来。**再配一把只有`trade`的密钥就能跟合作方一样分开用**：
  `PERP_API_KEYS=partner-a:密钥:trade|ops,partner-trade:另一个密钥:trade`，`make sim-client`会自动识别（也可以手动设`SIM_TRADE_KEY_ID`/`SIM_TRADE_KEY_SECRET`）。
  之后交易类请求（下单、查询、深度、WebSocket、结束本轮）用`trade`密钥，页面标了运营的请求（充值、提现、发额度、设投保、冻结/解冻、设指数价）用`ops`密钥，
  由页面用请求头`X-Sim-Scope: ops`声明，代理据此选密钥、不转发这个头。页面选错密钥，或者服务端把某个接口的权限范围分错，会直接返回`forbidden`
- 金额和盈亏的计算用了JS的浮点数，合作方应该用十进制库；显示够用，但不能拿它验证精度问题
- `/sim/config`是测试专用（页面启动时查代理配置），合作方没有

## 为什么需要一层代理

浏览器不能直接连我们的后端：

- 鉴权是API Key + HMAC签名， **密钥不能放进页面**
- 浏览器的WebSocket API不能自定义请求头，`/ws`握手的签名也做不了

所以页面只连一个薄的代理服务，代理持有密钥、对每个请求签名后转发，WebSocket也由它签名连上去再中继给页面。
这也说明：真实的合作方如果有网页端，同样得经过自己的后端转发，不能让浏览器直连我们。

```
浏览器页面  →  代理(tools/sim-client，持有密钥、签名、转发HTTP和WS)  →  contract-api / contract-engine
```

签名用的是生产代码里的`api.SignRequest`，跟合作方对接用的是同一套。

## 怎么用

```bash
cp deploy/.env.test.example deploy/.env      # 把PERP_API_KEYS里的CHANGE_ME换成随机串
make compose-test-up                         # 拉起整套系统
make sim-client                              # 打开 http://127.0.0.1:8088
```

想要一个有深度的订单簿（不然只有一个用户的话什么都成交不了），在`deploy/.env`里设`PERP_MIRROR_SYMBOLS=BTCUSDT,ETHUSDT`
（`contract-engine`读取），重启`compose-test-up`，见 [orderbook-sync.md](orderbook-sync.md)。

`scripts/sim-client.sh`会从`deploy/.env`里取第一把带`ops`权限的密钥和后端端口。可选参数见
`go run ./tools/sim-client -h`，环境变量`SIM_*`也能配置。

## 页面功能

- **账户**：新建账户并充值、切换账户，显示权益、可用余额、仓位保证金、挂单冻结、未实现盈亏、信用额度、轮次
- **交易**：限价/市价，开仓/平仓，杠杆，只减仓；点订单簿的价格自动填入；按余额或持仓的百分比填数量；预估名义价值、
  保证金和手续费
- **行情**：订单簿（引擎实时）、最新成交、K线（六个周期）、标记价/指数价/24h统计/预估资金费率
- **持仓和委托**：持仓（含浮盈亏、回报率、强平价估算，市价平仓、改杠杆）、当前委托（撤单、撤销全部）、条件单、
  委托历史、成交历史（含maker/taker角色）、资金流水、强平记录
- **运营抽屉**：冻结/解冻、发信用额度、扣减余额、设投保、结束本轮、设指数价
- **API调用日志**：每次调用的请求、响应、耗时，点击展开，方便看接口对接时到底发了什么、收到了什么
- **实时**：WebSocket推送深度、成交、K线、标记价、账户快照；每5秒用REST校准一次（WS不保证绝对不丢）

## 在页面上测试强平和盈亏

不依赖做市/行情情景：运营抽屉里的"设置指数价"能直接把指数价一步改到任意值（测试环境不开指数价的服务端跳变保护，
`PERP_INDEX_MAX_JUMP`留空），标记价跟着指数价走，足够手动制造强平和盈亏场景：

1. 新建一个账户， **只充值一点钱**（比如1000）
2. 杠杆10，选"市价"，点"100%"按钮，买入开多——满仓
3. 运营抽屉里"设置指数价"改到比开仓价低几个百分点，看浮亏（未实现盈亏、回报率、权益都在变）
4. 改到接近强平价（持仓表里有估算强平价）时，右下角会提示"仓位进入强平"，仓位状态变成"强平中"，强平单按保护价
   挂出（需要订单簿里有对手方成交，见上面"怎么用"配置`PERP_MIRROR_SYMBOLS`），完成后提示"强平完成"，仓位清零；
   "强平记录"标签页里有强平委托（委托价是保护价，成交价是实际吃到的价格），"资金流水"里有已实现亏损和手续费
5. 强平点大约在"亏损 = 保证金 - 维持保证金"处：10倍多头约下跌9.6%（未投保；投保后阈值收紧到80%，见 [liquidation.md](liquidation.md)）

**在页面上验证盈亏**：开仓后把指数价改高2%，持仓表里的未实现盈亏 = (标记价 - 开仓均价) × 数量，权益 = 可用余额 + 仓位保证金 +
未实现盈亏；
市价平仓后，"资金流水"里已实现盈亏 = (平仓成交价 - 开仓成交价) × 数量，余额 = 充值 + 已实现盈亏 - 手续费。

## 安全

代理持有`ops`权限的密钥（能充值、冻结、设指数价），所以：

- **默认只绑127.0.0.1**，监听其他地址会拒绝启动（`-allow-remote`可以强行放开，但等于任何人都能加钱扣钱）
- **只接受回环名字访问**（校验`Host`头），防DNS重绑定
- **`/api`、`/engine`、`/sim`必须带自定义请求头`X-Sim-Client`**：别的网站的页面借用户的浏览器发请求，没法在不触发
  CORS预检的前提下加自定义请求头，而代理不响应预检
- **WebSocket校验`Origin`**必须是代理自己的页面
- **不跟随重定向**：请求带着签名头，跟着重定向去了别的地址就把API Key送出去了

**已知的局限**：代理不认证调用方，也没有路径或方法白名单——同一台开发机上的任何本地进程或其他系统用户，加上`X-Sim-Client`头就能
经它用ops权限调用后端（加减余额、冻结账户）。它跟任何本机开发服务器（数据库、调试端口）是同一类风险，前提是开发机本身可信；
上面几条防的是浏览器里的跨站攻击，不是本机上的其他进程。不要在多用户共用的机器上运行，也不要暴露到网络上。

## 测试

`go test ./tools/...`（也包含在`go test ./...`里）覆盖：

- **代理**：转发时签名覆盖的路径/查询串/请求体跟实际转发的一致（用生产的验签方式重新算一遍）、`/api`前缀被去掉、
  没配密钥就不签名、三道防护、监听地址检查

页面本身没有自动化测试，是用无头Chrome通过DevTools协议驱动验证的，驱动的是页面上的真实点击：新建账户、充值、点盘口填价、
下单、成交、持仓、挂单、撤单、市价平仓、成交历史、资金流水；以及强平和盈亏场景——充值1000满仓10倍市价开多，指数价改低几个
百分点时页面显示的未实现盈亏与手算一致，改到强平价附近触发强平，强平单以保护价挂出、成交，仓位清零，强平记录和资金流水里
都有明细；另一个账户开仓后指数价改高，已实现盈亏与 (平仓价-开仓价)×数量逐分一致，余额与充值+盈亏-手续费一致。控制台无错误。

## 它发现过的问题

页面第一次实际交易就暴露了两个后端的真实缺陷（都已修复，见对应提交和测试）：

- **市价单撮合不成交**：`contract-api`把标记价存进市价单的`price`字段，引擎原样传给撮合，市价单变成"按标记价成交的
  限价单"，市价买只能吃低于等于标记价的卖单，几乎一笔都成交不了，见 [matching-and-settlement.md](matching-and-settlement.md)
- **每笔下单撤单固定多1秒延迟**：Kafka生产者用了kafka-go默认的`BatchTimeout`（1秒），同步单条写入要等满；
  默认的`RequiredAcks`还是不等确认。现在是10ms和等全部副本确认
