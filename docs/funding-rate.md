# 资金费率机制

永续合约锚定现货价格的核心机制：我们盘口价格相对指数价格的溢价，按周期（默认8小时）结算给
多空双方，让合约价格不会无限偏离真实市场价格。

## 标记价格、指数价格和溢价

- **指数价格**：反映外部真实市场价格，由外部行情源持续推送（`POST /index-price`），带接收时间，
  超过30秒没更新算断供。断供期间资金费率不采样、不结算，恢复后继续
- **标记价格**：由指数价、盘口基差、最新成交价取中位数得出，不是最新成交价本身，见 [mark-price.md](mark-price.md)。
  资金费率**结算时**用它算仓位的名义价值（资金费=名义价值×费率），但**溢价本身不用标记价算**
- **溢价**：我们盘口相对指数价的偏离，用**冲击价格**算（币安的口径），见下面"溢价指数"一节。
  以前用`(标记价格 - 指数价格) / 指数价格`，但标记价被限制在指数价和"指数价加盘口基差"之间，这个溢价会被压缩到
  不超过盘口基差，资金费率偏小

## 采样与结算

`FundingService`两个方法，由`contract-engine`里一个ticker定时调用（`FundingSampleIntervalMs`，
默认1分钟一次）：

- **`SampleOnce`**：给这个engine实例**负责的**每个启用合约采一次样，把这一刻的溢价累加进这个symbol当前资金
  费率周期的累加器（存在Redis里）。溢价要读订单簿，而分片部署下非owner实例的本地订单簿是空的，所以只有
  拥有这个symbol的实例才采样。指数价缺失/断供、盘口不够深就跳过这个合约，不能当0处理，那样会把
  溢价算成一个有偏向性的错误值。
- **`SettleIfDue`**：判断每个合约是否跨过了下一个结算时间点，跨过了就结算。

结算时间点 **不单独存"下次结算时间"**，直接从当前时间和结算周期长度算出来——对齐到从
Unix纪元起的整点边界，`funding_interval_hours=8`时天然落在UTC 00:00/08:00/16:00：

```go
boundary := (now / intervalMs) * intervalMs
```

## 溢价指数：冲击价格

```
溢价 = [ max(0, 冲击买价 - 指数价) - max(0, 指数价 - 冲击卖价) ] / 指数价
```

- **冲击买价 / 冲击卖价**：按这个合约的`funding_impact_notional`（USDT，默认10000）去吃订单簿的买盘 / 卖盘，
  吃完这么多名义价值（价格×数量）的平均成交价。代码是`matching.Book.ImpactPrices`
- 买卖价都高于指数价：合约比现货贵，溢价为正（取冲击买价）；都低于指数价：溢价为负（取冲击卖价）；
  指数价夹在冲击买价和冲击卖价之间：溢价为0
- 算出来是采样值，累加进当前周期的累加器，结算时取均值（TWAP）再夹到`±funding_rate_cap`，这部分没变

**为什么用冲击价格而不是买一卖一中价**：中价只要在买一挂一手就能拉动。冲击价格要吃掉足够的名义价值，想影响它得在盘口上
摆出接近`funding_impact_notional`那么大的单子（影响与"单子大小 / 冲击名义金额"成正比）。例子（指数价65000，名义金额10000）：

| 盘口                                                             | 中价基差 | 冲击价格溢价 |
|------------------------------------------------------------------|----------|--------------|
| 买65000×100，卖65100×100（正常）                                 | 0.077%   | 0            |
| 同上，但买一被拉到65650、只挂0.01个（656.5，不到名义金额的7%）    | 1.04%    | 0.065%       |
| 买盘先吃65100×0.1（6510），剩下的吃65000；卖65200×100            | -        | 1/999≈0.1001% |

**盘口不够深就不采样**：买盘或卖盘任何一侧的总名义价值不到`funding_impact_notional`，这一个合约这一轮不采样
（不拿一侧的价格凑合，否则撤掉一侧挂单就能控制溢价）。一个周期里一个样本都没采到，资金费率就是0。所以：

- `funding_impact_notional`要**小于**盘口两侧各自的深度，按合约调（`UPDATE coins SET funding_impact_notional = ? WHERE symbol = ?`，
  下一轮采样生效）；配成0表示这个合约不采样
- 采样被跳过时每个合约只在原因变化时打一条`[WARN] 资金费率采样被跳过`（恢复时打`[INFO] 资金费率采样恢复`），
  不会每分钟刷屏；测试环境没开订单簿镜像时盘口是空的，看到这条是正常的
- 已经建过库的环境需要重建库才有这一列（见 [architecture.md](architecture.md)"数据库"一节）

## 结算顺序：先落审计记录，再转账

结算时 **先**把这个周期的资金费率记录插入`funding_rate_history`（这张表的
`UNIQUE KEY(symbol, funding_time)`保证同一个周期只会成功插入一次）， **再**给每个仓位划转
资金费。这个顺序不能反过来：

如果先转账、划到一半失败才发现落库失败，下一次tick会因为查不到这个周期的记录而认为还没
结算过，重新把已经转过账的仓位再转一遍，造成重复扣款/派发。现在这个顺序下，最坏情况是
"这个周期有仓位划转失败、没收到/没扣到资金费"（单个仓位划转失败只记日志，不中断其它仓位），
不会出现同一笔钱被重复结算。

## 划转公式

```
多头视角的资金费 = 仓位名义价值 × 资金费率
```

正数=多头要付出去的钱（费率为正说明合约价格比指数价格贵，多头是推高价格的一方）；空头是
多头的镜像，符号相反。资金费率会先clamp到`±funding_rate_cap`（每个合约可配置的上限）。

## 查询接口

- `GET /funding/rate?symbol=xxx`：当前周期到目前为止的TWAP均值当预估费率（跟结算前展示
  的逻辑相同，不是等结算那一刻才有数），加上下一个结算时间点
- `GET /funding/history?symbol=xxx`：历史结算记录
