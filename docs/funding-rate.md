# 资金费率机制

永续合约锚定现货价格的核心机制：标记价格相对指数价格的溢价，按周期（默认8小时）结算给
多空双方，让合约价格不会无限偏离真实市场价格。

## 标记价格 vs 指数价格

这是两个独立的概念：

- **标记价格**：反映我们自己盘口的最新成交价（MVP阶段就是"最新成交价"本身，不做平滑）
- **指数价格**：反映外部真实市场价格，由外部行情源推送（`POST /index-price`），MVP阶段
  先靠脚本/运营手动喂，以后可以直接换成接入交易所行情的适配器——下游资金费率的采样/
  结算逻辑完全不用改，只是换一个写入方

资金费率就是这两者的溢价：`premium = (标记价格 - 指数价格) / 指数价格`

## 采样与结算

`FundingService`两个方法，由`contract-engine`里一个ticker定时调用（`FundingSampleIntervalMs`，
默认1分钟一次）：

- **`SampleOnce`**：给每个启用的合约采一次样，把这一刻的溢价率累加进这个symbol当前资金
  费率周期的累加器（存在Redis里）。标记价/指数价任一缺失就跳过，不能当0处理，那样会把
  溢价算成一个有偏向性的错误值。
- **`SettleIfDue`**：判断每个合约是否跨过了下一个结算时间点，跨过了就结算。

结算时间点**不单独存"下次结算时间"**，直接从当前时间和结算周期长度算出来——对齐到从
Unix纪元起的整点边界，`funding_interval_hours=8`时天然落在UTC 00:00/08:00/16:00：

```go
boundary := (now / intervalMs) * intervalMs
```

## 结算顺序：先落审计记录，再转账

结算时**先**把这个周期的资金费率记录插入`funding_rate_history`（这张表的
`UNIQUE KEY(symbol, funding_time)`保证同一个周期只会成功插入一次），**再**给每个仓位划转
资金费。这个顺序不能反过来：

如果先转账、划到一半失败才发现落库失败，下一次tick会因为查不到这个周期的记录而认为还没
结算过，重新把已经转过账的仓位再转一遍，造成重复扣款/派发。现在这个顺序下，最坏情况是
"这个周期有仓位划转失败、没收到/没扣到资金费"（单个仓位划转失败只记日志，不中断其它仓位），
不会出现同一笔钱被重复结算。

## 划转公式

```
多头视角的资金费 = 仓位名义价值 × 资金费率
```

正数=多头要付出去的钱（费率为正说明合约价格比指数价格贵，多头是推高价格的一方）；空头是
多头的镜像，符号相反。资金费率会先clamp到`±funding_rate_cap`（每个合约可配置的上限）。

## 查询接口

- `GET /funding/rate?symbol=xxx`：当前周期到目前为止的TWAP均值当预估费率（跟结算前展示
  的逻辑相同，不是等结算那一刻才有数），加上下一个结算时间点
- `GET /funding/history?symbol=xxx`：历史结算记录
